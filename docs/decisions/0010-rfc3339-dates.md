# ADR 0010 — Dates use RFC 3339 with a mandatory offset

**Status**: Accepted
**Date**: 2026-08-05

## Context

Documents carry timestamps: when results were generated, when the competition took place. ISO
8601 is the reflex answer, but it is a large and permissive standard — week dates, ordinal dates,
intervals, varying precision, optional time zones.

A standard should restrict, not inherit permissiveness.

## Decision

Use **RFC 3339**, a strict subset of ISO 8601, with the UTC offset **mandatory**:
`2026-05-17T16:42:00+02:00`. Bare calendar dates (`2026-05-17`) are allowed where a time of day
carries no meaning.

## Consequences

- Every target language parses and emits RFC 3339 natively.
- A result timestamp is unambiguous the moment it crosses a border — which, for a format aimed at
  international use, it does by construction.
- Producers in a single time zone must still emit an offset. A trivial cost against the class of
  bugs it removes.

## Alternatives considered

**Unix timestamps** — compact and unambiguous. Rejected: unreadable by eye, against the
hand-readability requirement.

**Full ISO 8601** — maximum flexibility. Rejected: it would force every consumer to handle
formats no producer will realistically emit.

**Optional offset** — friendlier to local-only producers. Rejected: it makes every timestamp
ambiguous for the consumer, which cannot know whether the offset was omitted or the time was UTC.
